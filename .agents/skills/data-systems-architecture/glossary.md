# Glossary

Compact definitions; chapter numbers route through [SKILL.md](SKILL.md). Read the chapter for assumptions and mechanisms.

- **ACID** — Atomicity, consistency, isolation, durability; guarantees have specific scopes. (8)
- **Amplification** — Physical read/write/storage cost beyond logical work or live data. (4)
- **Anti-entropy** — Background comparison and repair of divergent replicas. (6)
- **Atomic commit** — Participants agree whether all transaction changes commit. (8)
- **Atomicity** — Transaction changes commit together or abort together. (8)
- **Avro** — Encoding using writer schemas and reader-schema resolution. (5)
- **Backpressure** — Slowing upstream work when downstream capacity is insufficient. (12)
- **Backward compatibility** — New readers understand old writers' data. (5)
- **Batch** — Processing a bounded, identified input dataset. (11)
- **Bloom filter** — Probabilistic membership structure allowing false positives. (4)
- **B-tree** — Ordered hierarchical pages supporting lookups and range access. (4)
- **CAP** — Partition-time tension between linearizability and formally defined availability. (10)
- **CAS** — Compare-and-set; condition and update form one atomic operation. (8, 10)
- **Causality** — Dependency through local order or communicated observations. (6, 10)
- **CDC** — Change data capture from authoritative database changes. (12)
- **Checkpoint** — Recoverable state coordinated with processing progress. (12)
- **Columnar storage** — Values stored by column for selective scans/compression. (4)
- **Compaction** — Rewriting retained state while removing obsolete representations. (4, 12)
- **Compensation** — A new business action addressing an earlier effect. (13)
- **Consensus** — Agreement on proposed decisions under explicit fault/progress assumptions. (10)
- **Consistent hashing** — Key placement minimizing movement as assignments change. (7)
- **Consistent prefix** — Observations preserve a relevant ordered history's prefix. (6)
- **CQRS** — Separate command responsibilities from read representations. (3)
- **CRDT** — Replicated type with specified merge/convergence semantics. (6)
- **Data grain** — Exactly what one analytical fact/row represents. (3, 11)
- **DataFrame** — Tabular transformation interface bridging relational and array-oriented work. (3, 11)
- **Derived state** — Representation reproducible from retained sources and transformation. (1, 13)
- **Durability** — Committed state survives the specified failure model. (8)
- **Durable execution** — Persisted workflow progress supporting recovery/replay. (5)
- **Event sourcing** — Authoritative accepted-event history from which state is derived. (3)
- **Event time** — Timestamp describing when an event occurred at its source. (12)
- **Eventual consistency** — Convergence under stated propagation and quiescence conditions. (6)
- **Exactly-once effect** — One visible effect despite possible repeated execution, within scope. (8, 12)
- **Fencing token** — Ordered ownership epoch enforced by the protected resource. (9)
- **Forward compatibility** — Old readers understand new writers' data. (5)
- **HNSW / IVF** — Approximate vector-search structures trading search work for recall. (4)
- **Idempotency** — Repetition has the same intended effect as one operation. (8, 13)
- **Inbox / outbox** — Transactional received-event claim / durable publication intent. (8, 13)
- **Integrity** — Preservation of correct facts and invariants, distinct from freshness. (13)
- **Inverted index** — Terms map to matching records/postings. (4)
- **Isolation** — Restrictions on interactions among concurrent transactions. (8)
- **Lamport clock / HLC** — Logical ordering; HLC also approximates physical time. (10)
- **Lease** — Time-limited ownership; expiry does not stop a paused worker. (9)
- **Linearizability** — Operations appear instantaneous and respect real-time precedence. (10)
- **Liveness / safety** — Eventual progress / absence of forbidden behavior. (9)
- **Lost update** — Concurrent read–modify–write cycles overwrite accepted changes. (8)
- **LSM tree** — Buffered writes with immutable sorted runs and merging. (4)
- **Materialized view** — Stored result maintained from source data. (2, 12)
- **Monotonic reads** — A session's observed version does not move backward. (6)
- **MVCC** — Multiple stored versions support snapshot visibility. (8)
- **Normalization** — Represent independently changeable facts without redundant copies. (3)
- **OLAP / OLTP** — Analytical scans/aggregation / operational transaction-oriented workloads. (1)
- **Partial failure** — Some components or interactions fail while others continue. (9)
- **Phantom** — Concurrent changes alter a predicate's matching records. (8)
- **Processing time** — Time an operator handles an event. (12)
- **Projection** — A derived representation built from authoritative inputs. (3, 13)
- **Quorum** — A protocol-defined participating set; overlap alone is insufficient. (6, 10)
- **Read-your-writes** — A session sees its own accepted changes. (6)
- **Reconciliation** — Compare evidence and resolve missing, uncertain, or inconsistent effects. (13)
- **Replication / sharding** — Copying data / dividing its ownership. (6, 7)
- **Schema-on-read/write** — Interpret structure while reading / enforce while writing. (3)
- **Serializability** — Committed transactions equivalent to some serial execution. (8, 10)
- **Shuffle** — Redistribute records by key; some implementations also sort. (11)
- **Snapshot isolation** — Consistent snapshot with write-conflict rules; permits write skew. (8)
- **SSI** — Serializable snapshot isolation using dependency tracking and aborts. (8)
- **SSTable** — Immutable sorted key/value segment. (4)
- **Strict serializability** — Serializability with real-time precedence. (10)
- **System of record** — Authoritative facts for a defined ownership scope. (1)
- **Timeliness** — How soon observations reflect accepted state changes. (13)
- **Tombstone** — Deletion marker retained to prevent stale-state resurrection. (4, 12)
- **Total-order broadcast** — Agreed delivery order under the protocol's guarantees. (10)
- **2PC / 2PL** — Two-phase commit / two-phase locking; different mechanisms. (8)
- **Version vector** — Per-replica progress metadata distinguishing causal/concurrent versions. (6)
- **WAL** — Write-ahead log supporting durable recovery of changes. (4)
- **Watermark** — Stream progress bound/estimate under explicit timestamp assumptions. (12)
- **Write skew** — Concurrent decisions on a shared premise update different records. (8)
